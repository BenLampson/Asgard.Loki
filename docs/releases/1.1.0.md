# Asgard.Loki 1.1.0

Image generation now has an optional unified workflow. Applications register their upstreams once, send a `LokiImageGenerationRequest`, and consume a common result without assembling each provider's native request body. Full native calls and existing Image APIs remain available.

## Unified image generation

A `LokiImageProvider` registers public model names. Each model can contain multiple complete upstream providers, with an independent address, actual model, API key, HTTP client policy and handler. `LokiImageFactory` creates clients with independent default round-robin selection. Compatible official services and relay endpoints can share the same singleton handler; a handler object or registered name is selected explicitly.

Handlers own reliable request mappings. For example, image count maps to OpenAI's `n` or SiliconFlow's `batch_size`. A set optional parameter requires both a handler mapping and a declaration for the actual upstream model. Unsupported parameters, unsupported values and collisions with native extensions throw `LokiImageParameterException` before generation HTTP is sent. Diagnostics identify the selected provider, actual model, parameter, requested value and support constraints.

Missing fields preserve upstream defaults. Parameters are never silently dropped, quality is not converted into size, and a failed or unsupported target is not replaced with another target. Ark's maximum group size is not treated as an exact count: unified `Count = 1` is mapped to single-image mode; exact counts above one require native group-generation semantics.

### Common results, original responses and image bytes

Unified results retain complete original JSON, available exact HTTP response bytes/status/media type, selected upstream identity and ordered image views. Image-level errors and partial success remain visible. Empty-image results and pending/failed/unknown task states do not become successful image generation.

Applications explicitly call `GetImageContentAsync` to obtain bytes from supplied binary, Base64 or a returned URL. Decoding and downloads use byte limits, retain declared image media types where available, and never attach generation keys to content requests. The application chooses whether and where to save files. A download failure keeps the original generation result and never triggers another generation.

### Native access and asynchronous generation

Use `NativeParameters` for supplier-specific extensions alongside unified parameters. Overlapping native and unified fields fail instead of choosing silent precedence.

`GenerateNativeAsync` accepts a full native body and an explicit `ProviderId`, so a heterogeneous public model cannot randomly dispatch native JSON to another protocol. Native calls bypass unified capability declarations while retaining native validation and fixed-target model binding.

Ali's modern asynchronous image-generation service has an explicit task handler. Submission returns a persistent reference; `GetAsync` performs one query against the original complete target. Changed server, model, credential identity, handler or operation configuration invalidates that reference. No background polling or callback host is added.

Custom handlers can implement the public handler contracts or reuse the mapping base class.

## Usage and compatibility

All 66 packages share version **1.1.0**, targeting **.NET 10 / C# 14**. Use matching package versions:

```sh
dotnet add package Asgard.Loki --version 1.1.0
dotnet add package Asgard.Loki.Image.OpenAI --version 1.1.0
```

After registering a `LokiImageFactory`, standalone calls use `factory.CreateClient()`. Applications can also register `ImageOptions.GenerationFactory` and use:

```csharp
var result = await loki.Image.Generation.GenerateAsync(
    new LokiImageGenerationRequest
    {
        Model = "pictures", // The public model registered by the application.
        Prompt = "A watercolor cat beside a sunny window."
    },
    cancellationToken);
```

Existing `loki.Image.GenerateAsync(ImageGenerationRequest)`, target-typed `new()` calls, native adapters, image streaming and image editing retain their interfaces. Unified generation uses the separate `.Image.Generation` property, avoiding ambiguous overloads.

The Image capability now directly references capability-independent Infrastructure and Microsoft.Extensions.Http for factory contracts and explicit bounded image-content retrieval. The entry package still depends only on Abstractions; no supplier or sibling capability dependency is introduced.

## LLM output-format declarations

This release also adds `LlmTarget.AllowedOutputFormats`: explicit output-format declarations per complete target and SDK protocol. Configured declarations are checked before invoking the adapter and participate in Session binding. Unsupported explicit formats fail without downgrade or rerouting; native request bodies and schemas remain unchanged. Unconfigured declarations retain existing native forwarding behavior.

See the [native LLM output-format contracts and examples](https://github.com/BenLampson/Asgard.Loki/blob/v1.1.0/docs/llm-output-formats.md).

## Validation and limits

The release includes 82 unified-image tests and 13,805 offline tests across 66 projects. Coverage includes official/relay target identity, singleton handler reuse, native wire mappings, unsupported parameters/ranges/conflicts, original response preservation, binary retrieval, task binding and existing-interface compatibility.

The release process requires Windows and Linux build, offline tests, packing and package-boundary checks. NuGet publication uses the explicit `publish` mode for version `1.1.0` through the repository's OIDC trusted-publishing workflow.

Offline tests do not establish real account/model availability, optional-parameter effects or generated-image quality. No new real-provider image validation is claimed. This remains a pure .NET SDK, with no gateway server, billing, general storage, automatic tool execution, generation retry or target failover.

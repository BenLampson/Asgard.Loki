# Azure offline protocol tests

Run the xUnit v3 executable after building this project in Release, or use the repository's ordinary offline test entry point. No network, credentials, Azure account or Redis is needed.

Seven complete-call JSON fixtures are authored independently of the provider and converter: caller Chat/Responses inputs, v1/dated final Chat wire bodies, final Responses wire body and both complete native results. Tests compare entire JSON trees, including unknown members, filters, encrypted reasoning, schema wrappers, original tool association IDs and exact large integers. Only deployment/stream/routing changes are intentional. Conversion integration separately uses a representable common-subset fixture; it does not claim conversion of every Azure-specific field.

Authentication tests use a mutable deterministic clock and borrowed token source. Lifecycle tests fragment response bytes, inject EOF/disposal failures and cancellations, and check client ownership. Session tests use `MemoryDistributedCache` and the explicit test coordinator. Token refresh is simulated; the suite is protocol verification, not live cloud authentication/model verification. Independent raw SSE fixtures and full JSON event goldens cover both protocols, unknown events, native tool associations, asynchronous filter/usage tails and SSE identity/retry metadata. Separate lifecycle/transport tests cover missing/repeated/late terminals, changed identity/status, total byte and tail/choice bounds, cancellation, malformed encoding and EOF/disposal failures. The suite currently has 497 cases; complete JSON tests alone are not used as evidence for streaming support.

The independently authored `Fixtures/compaction.json` supplies complete original/retained windows, owned-response requests, native errors and three explicit endpoint profiles. Its 95 compaction cases use the public SDK and direct adapter boundaries to cover both API Key and borrowed external credentials, whole-window/tool-call association preservation, strict raw body/encoding/length/media contracts, binary errors, exact byte limits, actual-target mutation, EOF/disposal/final cancellation, token-source/expiry drift, default binding compatibility, feature selection, Session reconstruction and response ownership. A compact result ID is never indexed as a generated response. Dated compaction routing is an offline profile, not proof that a dated Azure version accepts the operation.

`Fixtures/realtime.json` is an independently authored native transcript: two Azure handshake profiles, full caller/wire events and a complete server sequence including original tool associations, native audio/transcription fields, preview event names, errors, failed/cancelled/completed responses and later rate-limit events. The 96 Realtime cases compare the full transcript and verify strict fragmented UTF-8/JSON, duplicate/Unicode failures, exact bidirectional message-byte limits, unknown business model fields, input snapshots, cancellation before/after native IO, one-reader and close/disposal behavior, fixed target/query escaping, unsupported/failed handshake handling, identity/expiry drift through handshake and duplex IO, Session loss, configuration/principal changes and explicit reconnect with a rotated token without replay. In-memory WebSocket doubles open no port. Protocol fixtures do not establish Azure model/version/region acceptance, audio quality or real Entra authentication.

The 151 native text Completions cases use independently authored `text-completions.json` and `text-completions.sse`: complete caller/v1/dated bodies/results and a full multi-choice text/logprobs/filter/usage/unknown-tail transcript. Tests compare whole native data and SSE metadata across both authentication kinds and all explicit endpoint profiles. Further cases cover request/prompt shapes and byte boundaries before authentication, full JSON structural/encoding/length/media errors, HTTP200/native/binary error preservation, actual target/method mutation, snapshots before token awaits, stable default/explicit-policy binding, Session reconstruction and text-ID isolation. A separate text lifecycle proves text/logprobs generation detection, original index/identity associations, all-choice finish plus DONE, bounded tail/choice counts, delayed filter-terminal rules and suppression of the entire pending tail on late EOF/disposal/client/cancellation or source-expiry failure. Early consumer exit does not drain/retry. Real Azure deployment/version acceptance and text quality remain unverified.

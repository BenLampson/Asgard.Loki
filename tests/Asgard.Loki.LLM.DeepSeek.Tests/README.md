# DeepSeek native tools offline tests

The xUnit v3 executable currently runs tests. `Fixtures/tools.json` is authored independently of production code and contains full Search/Fetch request/result windows, minimal/default omission, explicit null/false/empty values, Unicode query/page text, duplicate ranked URLs, unchanged low/high scores, exact integers and a native error. Every call uses a substitute HTTP handler; no real Key, DNS/page fetch, network, Redis or model is required.

Tests compare entire original and transmitted JSON and complete native results. They verify Unicode scalar/query/URL bounds, final request bytes before factory creation, unknown fields, explicit model-free operation, unchanged request snapshots, empty results/content, nullable metadata presence, finite scores without thresholds and binary/native/HTTP error bodies. Transport tests use nonseekable three-byte fragments and inject length/encoding/duplicate/media/size/actual-target/EOF/read/disposal/cancellation failures. Configuration cases verify explicit Key isolation, safe default serialization/display, named client/root/port behavior, no implicit attempts, per-call ownership and concurrent clients with independent target/credential pairs. Results are not model quality, service availability or real DeepSeek integration evidence.

Build Release with one MSBuild worker, then run `dotnet test --project tests/Asgard.Loki.LLM.DeepSeek.Tests/Asgard.Loki.LLM.DeepSeek.Tests.csproj -c Release --no-build`, or use the ordinary repository offline test entry point. Live validation is separate and unperformed.

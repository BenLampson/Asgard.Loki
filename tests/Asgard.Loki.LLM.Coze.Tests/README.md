# Coze native chat offline contracts

Independent synthetic v3 create acknowledgement, explicit retrieve/message-list and two-level SSE fixtures, authored before implementation. Caller and complete/stream wire are separate literal objects; expected events and native SSE transcript are separate literal resources. These are offline native data contracts, not live captures or a model catalog.

The request retains all roles/types, opaque tool call/result association content, object_string media references, exact values, false/null and unknown parameters; user_id is explicit and conversation_id belongs in the query. auto_save_history=false is deliberately retained; it does not claim later retrieval will be accepted by a live service. Acknowledgement status in_progress is not generated output. Retrieve required_action, all ordered function/tool/multiple answer/follow-up messages and reasoning are retained without local execution, polling, synthesis or last-answer projection.

Chat ID, conversation ID, message ID, tool IDs and SSE transport ID are distinct. The SSE window includes two independently completed answers, original tool/reference content, a chat terminal, opaque future metadata and a quoted native DONE payload. The implementation must also preserve the documented unquoted DONE form; neither event name nor business done fields alone may manufacture a JSON terminal.

Sources: [create](https://docs.coze.cn/developer_guides_chat_v3), [retrieve](https://docs.coze.cn/developer_guides_retrieve_chat), [chat-scoped messages](https://docs.coze.cn/developer_guides_list_chat_messages), [official native SDK](https://github.com/coze-dev/coze-py/blob/main/cozepy/chat/__init__.py). The native API selects a bot rather than an underlying model; supplier target metadata must label BotId honestly. No bot management, conversation administration, workflow host, file transfer, default user, implicit history saving or synchronous-completion/polling wrapper is included.

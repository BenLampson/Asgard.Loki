# Coze native chat offline contracts

Independent synthetic v3 create acknowledgement, explicit retrieve/message-list and two-level SSE fixtures, independently authored. Caller and complete/stream wire are separate literal objects; expected events and native SSE transcript are separate literal resources. These are offline native data contracts, not live captures or a model catalog.

The request retains all roles/types, opaque tool call/result association content, object_string media references, exact values, false/null and unknown parameters; user_id is explicit and conversation_id belongs in the query. auto_save_history=false is deliberately retained; it does not claim later retrieval will be accepted by a live service. Acknowledgement status in_progress is not generated output. Retrieve required_action, all ordered function/tool/multiple answer/follow-up messages and reasoning are retained without local execution, polling, synthesis or last-answer projection.

Chat ID, conversation ID, message ID, tool IDs and SSE transport ID are distinct. The SSE window includes two independently completed answers, original tool/reference content, a chat terminal, opaque future metadata and a quoted native DONE payload. The implementation must also preserve the documented unquoted DONE form; neither event name nor business done fields alone may manufacture a JSON terminal.

Sources: [create](https://docs.coze.cn/developer_guides_chat_v3), [retrieve](https://docs.coze.cn/developer_guides_retrieve_chat), [chat-scoped messages](https://docs.coze.cn/developer_guides_list_chat_messages), [official native SDK](https://github.com/coze-dev/coze-py/blob/main/cozepy/chat/__init__.py). The native API selects a bot rather than an underlying model; supplier target metadata must label BotId honestly. No bot management, conversation administration, workflow host, file transfer, default user, implicit history saving or synchronous-completion/polling wrapper is included.

The native JSON tests executes tests with fake HTTP only. Whole literal caller/wire/ack/retrieve/messages resources verify single-call behavior, all native roles/tools/answers/reasoning/unknown data, exact values, explicit user/query identity, native status/required_action and persistable target-bound references. Tests cover every target/policy/credential drift, invalid IDs/Unicode/reserved paths before factory creation, request snapshots, native/HTTP/binary errors, byte/length limits, actual-method/URI changes, cancellation and owned-resource versus borrowed-factory lifetime. No unnecessary cache is introduced. These JSON tests do not establish SSE or live Bot/model behavior.

The full supplier executable has tests, including tests. Independent literal expected windows and SSE transcript are compared through the public client. Both actual DONE lexical forms retain their original data; known Chat/Message JSON, opaque future events, two independently completed answers, tool/reasoning and required_action/failed outcomes stay raw. Message/Chat/tool/transport ID domains remain separate, even when their string values coincide. A Message terminal cannot complete the chat; incomplete messages, mismatched status/identity/type, duplicate/late events, missing done, raw errors before/after done, framing/encoding/length/byte/association/tail limits, read/disposal/URI/final-cancellation faults cannot first release global terminals. The native reference enables only an explicit subsequent query, with no automatic polling or local execution.

Run locally after Release build: `dotnet test --project tests/Asgard.Loki.LLM.Coze.Tests/Asgard.Loki.LLM.Coze.Tests.csproj -c Release --no-build`. All HTTP is substituted; the fixed-service client introduces no cache or model Session. No actual credential/account/Bot request or model/option/output/audio quality has been validated.

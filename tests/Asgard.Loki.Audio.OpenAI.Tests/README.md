# OpenAI Speech offline protocol tests

Run the Release build of `Asgard.Loki.Audio.OpenAI.Tests.csproj`, then its xUnit v3 executable, or use the repository offline test script after building the solution. All 378 cases run against a local replacement HTTP handler (103 speech binary/request, 70 speech SSE, 99 nonstream file-operation and 106 transcription SSE cases).

`Fixtures/native.json` and `convenience.json` are independent complete wire requests, not generated by provider code. `terminal.json` records the complete SDK HTTP metadata terminal; it is not an upstream SSE event. Assertions also verify the full byte stream, intermediate cumulative counts, exact header values, route/target identity and absence of fabricated native usage/events.

SpeechReadStream injects short/long/empty bodies, partial read faults, cancellation and asynchronous disposal failure. SpeechTestHttpClient independently observes client disposal. Malformed lengths, unexpected media types, raw HTTP/JSON/text errors and request snapshots are covered without real credentials or network access. The arbitrary byte samples include invalid UTF-8 and are intentionally not speech-quality or media-container validation.

`sse-request.json`, `sse-events.json` and `sse-terminal.json` are independent complete request/event/envelope samples for the declared delta/done shapes. Tests preserve raw data and unknown JSON, inherited/reset SSE identity, Base64 audio associations and native usage without recomputation. They reject missing/late/duplicate terminals, error events even after done, malformed UTF-8/JSON/Base64/usage, ambiguous duplicate members, truncated event tails and decoded-audio/HTTP-length confusion. Read, cancellation, early stop and disposal faults are checked through both direct adapters and the SDK core. Source provenance and the current rendered-reference limitation are recorded in the provider README; offline examples do not prove a live model's event behavior.

The five `file-*-request.json` goldens independently describe every serialized multipart part header/body for minimal, rich, diarization, context and translation scenarios. AudioMultipartWire reads the actual MIME bytes and normalizes only the random boundary; it does not use production payload construction to generate expected parts. JSON and diarization response files contain complete raw native result examples, including language/segment/word/speaker/logprob/usage/unknown fields. Subtitle and unknown-encoding text bytes are kept exact. Tests cover current-position/nonseekable upload, no source disposal, one serialization, partial upload/no failover, raw HTTP/business errors, malformed/truncated/length/format responses, cancellation and disposal failures. Those are native wire/ownership tests, not real-media, per-model parameter-effect or language-quality validation.

`transcription-plain-stream-request.json` and `transcription-stream-request.json` independently describe full native streaming MIME bodies. `transcription-stream-events.json` and `transcription-stream-terminal.json` retain complete delta/segment/done JSON and native/SSE identity separately. Interleaved ids resolve without a guessed text merge; the final native text and usage deliberately differ from naive concatenation/arithmetic. Numeric boundary tests reject reversed high-precision times and fractional bytes without rounding, while preserving valid numeric lexemes. Tests exercise malformed optional metadata, id reopening/orphans/limits, duplicate/late/missing terminals, HTTP/SSE errors with raw error-event identity, length/encoding/read/disposal/cancellation failures and early stop. All are offline native protocol tests; none certifies model accuracy or speaker quality.


## Explicit compatible configurations

Independent Fixtures/Compatible/siliconflow-audio.json goldens verify configured SiliconFlow voice-based binary speech and multipart transcription through the existing public SDK adapters. Cases cover actual model/public route and independent credentials, complete native/custom JSON retention, absent defaults, literal/repeated/empty multipart parts, original audio/result/errors, borrowed ownership and delayed terminal state. No brand package, relaxed voice policy, live provider call, reference-only voice/SSE/translation acceptance or model-quality claim is added by these tests. The complete suite executes 393 offline cases, including 15 compatible-configuration cases.

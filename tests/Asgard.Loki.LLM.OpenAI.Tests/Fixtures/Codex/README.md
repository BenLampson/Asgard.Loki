# Explicit Codex backend protocol examples

Independent synthetic whole native requests/results and separately authored SSE/expected JSON windows. No real account/token/network was used. Content includes parallel tools with distinct item/call IDs, reverse-linked prior outputs, native reasoning/encrypted/compaction items, explicit instructions/store/settings/schema, exact numbers, false/null and future metadata. No provider implementation generated these expected resources.

The standalone alpha-search response is deliberately an opaque example: the reference call forwards request/response data and does not establish a stable public result schema. Keep its entire raw body/content type rather than inventing search DTOs, usage or file fetching. Optional native model fields remain caller data for this auxiliary call.

Calling contract reference: pinned [Codex adaptor](https://github.com/QuantumNous/new-api/blob/058c8231b68c51ee02abee15befcd720fee9f4a2/relay/channel/codex/adaptor.go) and [alpha-search handler](https://github.com/QuantumNous/new-api/blob/058c8231b68c51ee02abee15befcd720fee9f4a2/relay/alpha_search_handler.go). These are backend-specific examples, not a claim of a stable public OpenAI API or live account entitlement. Official [authentication](https://learn.chatgpt.com/docs/auth) and [external-token application mode](https://learn.chatgpt.com/docs/app-server#3c-log-in-with-externally-managed-chatgpt-tokens-chatgptauthtokens) distinguish subscription credentials from Platform API keys but do not document these HTTP endpoints. No sign-in, token refresh, auth-file loading or agent host is part of the SDK.

# Shared protocol acceptance data

`converse-text-complete.json` independently authors four complete text-protocol requests and their Converse request goldens, plus a complete native Converse result and four complete normalized response goldens. Inputs cover inline images, reverse-order parallel result replay, exact JSON Schema/integer values and explicit strict/tool-choice controls. Gemini object results remain native JSON; other protocols' text arrays remain text arrays, even when their text looks like JSON. Only synthetic root/message response IDs use `__ID__`; tool IDs and business IDs must never be normalized. Schema name is optional in native Converse. The data alone does not enable the mixed operation. References: [Converse](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.html), [JSON schema definition](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_JsonSchemaDefinition.html) and [tool specification](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ToolSpecification.html).

`nova-converse-stream-conversion.json` independently declares two complete 15-event native streams and their complete logical counterparts. It includes Unicode/empty text, sparse int32 indices, interleaved same-name calls, reverse block closure, split exact-integer/business-error arguments, original stop and required usage/zero-latency tail. `PreStreamOptions` is an independently retained preceding option declaration for compatibility checks. Source and expected event data are native declarations, not converter output. This artifact does not produce or claim target binary frames. See [Nova streaming](https://docs.aws.amazon.com/nova/latest/nova2-userguide/streaming-responses.html) and [ConverseStream](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ConverseStream.html).

`nova-converse-conversion.json` independently authors six complete native request goldens (Nova v1/v2, plus direct and nested Converse settings for each) and four complete response goldens. Both LLM conversion and AWS acceptance assemblies embed this test data under `BedrockConversion.Fixture`; no production package embeds or references it.

The samples contain ordered text/image/video containers, caller-owned S3 references, two same-name tool calls with reverse result order, explicit success/error and absent result status, null/false/zero, exact 9007199254740993 and an unchanged JSON Schema. Separate v1 low-effort/sampling and v2 high-effort/no-sampling bodies make native setting locations and schemaVersion policy reviewable. No expected JSON comes from a Loki converter, AWS signer, provider response capture or real model call. The artifact alone does not enable conversion or verify account/model acceptance.

References: [Nova v1 Invoke](https://docs.aws.amazon.com/nova/latest/userguide/using-invoke-api.html), [Nova v1 Converse](https://docs.aws.amazon.com/nova/latest/userguide/using-converse-api.html), [Nova 2 request/response schema](https://docs.aws.amazon.com/nova/latest/nova2-userguide/request-response-schema.html) and [Nova 2 core inference](https://docs.aws.amazon.com/nova/latest/nova2-userguide/core-inference.html). The official pages show different additionalModelRequestFields wrapper placements; both fixtures are explicit endpoint profiles, not a claim that either layout is universally accepted. Document input is Converse-only and is deliberately absent from successful Invoke goldens.

Nova2 request goldens were corrected on 2026-10-20: the three v2 positive requests retain their explicit 8192-token output limit and now use medium reasoning. AWS [extended thinking documentation](https://docs.aws.amazon.com/nova/latest/nova2-userguide/extended-thinking.html) prohibits high together with maxTokens. Dedicated negative variants retain that invalid combination and must fail; the positive high case explicitly omits the limit. This is a hand-authored fixture correction from the upstream contract, not converter-generated expected data or live acceptance. v1/raw supplier fixtures are unchanged.

# Vertex offline protocol tests

Three complete-call JSON fixtures are authored independently of the provider/converter: caller input, final native wire body and complete upstream result. Tests compare entire trees, preserving tool associations, opaque signatures, media/file and cache references, generation/schema/thinking settings, safety/grounding/usage, unknown null/false values and exact integers. These are forwarding fixtures; they do not establish that a live Vertex model accepts every field, particularly Developer API function IDs.

451 xUnit v3 cases exercise public SDK and direct-adapter boundaries with substitute HTTP, deterministic time, borrowed token/factory ownership and `MemoryDistributedCache` with an explicit coordinator. Response bytes are fragmented and EOF/disposal/cancellation failures are injected. The suite does not require keys, a Google account, network or Redis. Independent raw SSE and complete JSON event-sequence goldens cover native thought signatures, tools/IDs, grounding, unknown objects, exact numbers and event identity/retry. Separate lifecycle tests cover original finish/block reasons, precise ProtoJSON integer/enum forms, sparse/default indices, missing/repeated/reopened candidates, identity changes, late errors, raw byte/length and tail/candidate bounds, early exit, cancellation and release failures. Complete JSON tests alone do not establish stream support. Explicit complete/streamed conversion integration covers a representable text subset only.

Claude has three additional independent complete JSON fixtures (`claude-request`, `claude-wire`, `claude-response`) retaining tools/error results, signatures/redacted thinking, output schema, cache blocks/usage and unknown exact values. Forty added cases cover rawPredict routing/body version, conflicts and header/resource rejection, unchanged default Gemini binding bytes, token-refresh Session affinity, changed protocol/principal/version, native transport faults and explicit common-text conversion. Those complete JSON fixtures do not establish live acceptance or substitute for the separate SSE tests.

Claude SSE adds 58 cases and independent raw `claude.sse` / full `claude-events.json` goldens. They preserve block/tool indices and IDs, signed thinking/redacted content, partial JSON strings, exact values, cumulative usage and SSE metadata. Negative tests cover missing/reopened/duplicate/wrong block associations, duplicate tool IDs, changed reasons, truncation, late native/platform errors, raw byte/length and block/tail limits, encoding/cancellation/disposal. Default omitted block policy retains legacy bindings; explicit changed policy invalidates them. Snapshots, JSON-to-stream Session recovery/token rotation and explicit common-text conversion streams are verified offline only.

Express adds 67 cases and three independent full JSON fixtures (`express-request`, `express-wire`, `express-response`). The existing raw Gemini SSE and full event-sequence goldens verify the identical native event contract through its distinct short-resource/API-Key transport. Tests cover version roots, key-only headers, snapshots, fixed-target recovery, Key/resource/configuration changes, default identity isolation, raw bounds/late faults/cancellation, malformed registration and complete/streamed common-text conversion. No OAuth source or live Express account is used.

MaaS adds 74 JSON cases and independent `maas-request`, `maas-wire` and `maas-response` fixtures. They compare complete public-SDK wire/results, original tool call/result IDs and reasoning/schema/unknown fields; verify explicit project/location and publisher/model selection, source-await snapshots, token rotation/fixed-target Session recovery and configuration/principal changes; reject invalid credentials/endpoints/models/default headers and check original errors, exact byte/length, strict encoding, late reads/disposal/cancellation. The former SSE rejection regression is now a pre-cancel/no-acquisition regression; native SSE is covered separately below. These offline fixtures verify transport preservation, not upstream acceptance of every extension or real cloud identity.
MaaS SSE adds 62 cases and independently authored `maas-stream-wire.json`, raw `maas.sse` and full `maas-events.json` fixtures. They compare complete public SDK wire/events and original sparse choice/tool indices, ID associations, fragmented names/arguments, reasoning, exact values, unknown fields, SSE identity/retry and usage tails. Tests cover snapshots before token awaits, JSON/SSE Session recovery and token rotation, early exit and cancellation; missing/repeated/reopened/native finish/DONE, incorrect tool IDs/indices, changed identities, malformed encoding/JSON/boundaries, raw length/byte and finite-state limits, late errors/read/disposal/cancellation; and explicit Responses-to-native-Chat streaming with withheld completion on late failure. The first finish and all tails wait for DONE, EOF and disposal. The new MaaS binding domain requires fresh JSON-only predecessor Sessions. Standard Vertex, Express, core fingerprints and conversion-v24 remain unchanged; no real cloud identity/model call was used.

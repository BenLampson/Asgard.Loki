# Asgard.Loki.Image.Volcengine.Tests

Independent authored protocol vectors follow the [Ark native image API](https://console.volcengine.com/ark/region:cn-beijing/docs/image-generation-api), its [SSE event reference](https://console.volcengine.com/ark/region:cn-beijing/docs/image-generation-streaming-responses) and the [provider-owned streaming guide](https://github.com/volcengine/ark-cli/blob/main/skills/arkcli-gen/references/image-stream.md). They precede the supplier implementation and are not captured traffic or evidence of real model acceptance.

Four complete native requests cover text generation, scalar image URL, URL/data-URI image arrays, native group settings, stream true, false/zero/null/precise integer extension values and layer decomposition with omitted prompt. Complete response vectors retain URL/Base64 output, per-image errors alongside successful images, original layer names/bounding boxes/order, tools, usage and unknown fields. The model returned by a deployment can differ from the configured endpoint-model spelling; neither should be rewritten.

Three original SSE wires cover group partial success/failure, an interleaved unknown event, a final summary containing no image payload, a single-image result with no summary and an overall native error. Per-image failures must not be flattened into overall errors or discarded; the original `image_index`, SSE identity and error details remain intact. A final summary is not an OpenAI-style image payload, and an absent single-image summary must not cause a fabricated completed event. Fixtures do not imply an exact group result count from max_images, guarantee all requested images, or add host task IDs, polling, file placeholders, media fetching, tools execution, billing or model catalogs. All credentials, models, media and pixels are fictional.

39 offline xUnit v3 cases now verify the complete request/result vectors and actual public/native adapter entries, image-level versus whole errors, optional-prompt layers, native single/group termination, original SSE identity/order, snapshots, required byte/length/cancellation/disposal boundaries and replay refusal. Native partial failures remain results; no actual model/pixel/feature acceptance is claimed.

Jimeng Visual `jimeng-images.json` contains independently authored native `CVProcess` request/results and explicit AK/SK temporary-credential signing vectors. Expected request bytes and HMAC values come from Python standard `hashlib`/`hmac`, independently of production code. URL/Base64 arrays, business errors and signing errors remain separate native envelopes. The official [Visual SDK](https://github.com/volcengine/volc-sdk-python/blob/master/volcengine/visual/VisualService.py) defines the root POST, version and signing scope. Vectors are fictional local contracts, not live availability/quality evidence.

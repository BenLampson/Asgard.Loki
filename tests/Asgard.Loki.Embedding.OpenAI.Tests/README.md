# OpenAI Embeddings protocol tests

xUnit v3 tests use the public `AddEmbedding` / `loki.Embedding.EmbedAsync` path and an actual `OpenAiEmbeddingAdapter` with substitute HTTP handlers. Eight independently authored complete request goldens cover four input forms and two encodings. Synthetic native response fixtures cover original order/index association, preserved extensions and missing usage.

Rejection/lifecycle cases cover invalid inputs, dimensions and formats, missing/duplicate/foreign indices, incomplete vectors, malformed Base64/JSON and duplicate fields, HTTP/business errors, cancellation, API-root/authentication headers, secret-free options serialization and borrowed-factory/response lifetime. No live API, real Key, Redis, model tokenizer or embedding-quality evaluation is used.

The Jina compatibility checkpoint adds 19 cases (original 106 cases before the M3E/transport additions). Three independently authored [complete request/response fixtures](Fixtures/jina-compatible.json) verify text and dense/Base64-compatible output with native Jina options, raw fields/usage and original indices. Seven object-input boundaries, five output/bit-dimension boundaries, conflicting encoding fields, nullable dimensions and two generic numeric-shape acceptance examples establish the actual reuse limits. Packed arrays accepted without declared dimensions remain raw numbers, not certified native bit embeddings. Sparse replies are published-schema boundary samples, without a verified deployed sparse model claim. No production converter generates expectations, and no native Jina provider is implemented by these tests.

`m3e-profile.json` is an independently authored explicit canonical M3E text-embedding profile. It retains raw native model/input, original reordered indices/float values, optional missing root/item fields, usage/unknown metadata and HTTP error bytes. Five public SDK/profile cases verify canonical scalar/batch request and result fidelity, snapshot timing, raw HTTP errors and duplicate-index rejection. They do not establish a hosted Moka service, model acceptance, token/Base64 support or live availability.

Sixteen additional transport cases cover binary error bytes/content type, byte and declared-length limits, invalid raw/escaped Unicode (including unknown fields), media/charset mismatch, duplicate unknown members, request rejection before factory creation, exact response limits, target/header isolation and late read/stream/client-disposal/cancellation failures. Together with the seven Workers AI cases below, the complete project has 134 offline cases.

Seven Workers AI compatibility cases use independently authored [full wire vectors](Fixtures/cloudflare-profile.json): four scalar/batch and trailing-root combinations through the public SDK, HTTP/native business-error byte retention, and incompatible `ai/run` envelope rejection. They verify only the account-scoped canonical OpenAI Embeddings operation, not live Cloudflare model execution or native run wrapper conversion.

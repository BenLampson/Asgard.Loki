# Protocol acceptance fixtures

`source/` contains independently authored native request, complete-response and full stream transcripts for the four protocols. They include Unicode text, tool definitions, a stable original call ID, arguments/results, zero/false/null values, complete done events, usage and representative response envelopes. These are offline protocol examples, not captured live calls.

`golden/` contains separately specified target wire structures for the same semantic case. Expected JSON was authored from the protocol shapes, without invoking the production converter. Snapshots compare all object values and array/event ordering; object property order is insignificant. IDs, tool arguments and terminal events are not normalized away. Tests never rewrite fixtures automatically.

Known response envelope metadata and executed-request echoes remain available in `OriginalData` / `Metadata.Conversion.UpstreamData`. They are not interpreted as target requests or translated continuation state. Content, unknown fields and nested semantic configuration remain subject to conversion validation. Snapshot tests supplement the field, identity, HTTP pipeline and adversarial lifecycle tests; they do not replace them or prove model acceptance.

`schema/response-format.json` separately specifies complete modern Gemini, Chat, Responses and Claude requests for one structured-output case. Six directional snapshots check the complete target body, including unchanged Schema constraints, MIME enum versus legacy names, explicit output limits and wrapper metadata diagnostics. They are authored fixtures rather than converter-generated expected output; separate public SDK HTTP/SSE and negative cases verify actual transport wiring and strict rejection.

`schema/typed-source.json` independently specifies one complete typed Gemini source and complete Chat, Responses and Claude targets. Its nested types, nullable enum, quoted integer limits, zero/false/null, arrays, anyOf and example/default annotations are hand-authored. Three complete-request snapshots and six HTTP/SSE cases compare these expectations; separate adversarial tests cover exact int64 exponent/range handling, ProtoJSON names/nulls, property insertion order, alias conflicts and hard failure before HTTP for unsupported constraints. These fixtures verify the typed source output-schema dialect only, not typed target output.

`schema/typed-function.json` independently specifies the Gemini typed function definition and complete Chat, Responses and Claude request histories. Three snapshots and six final-wire HTTP/SSE cases retain the schema, named tool choice, call ID, argument JSON and result association. Each pure-data direction also replays the history back to Gemini while retaining the converted JSON Schema. Conflict/order/unknown-constraint/native-copy and pre-HTTP rejection cases complete the eighteen-test function-source checkpoint. No expected body is generated by the converter.

# Protocol acceptance fixtures

`tools/rich-results.json` independently authors complete source/target requests for six text-array directions and two Responses/Claude image/PDF-array directions. Arrays retain text boundaries, empty text, JSON-looking strings, original IDs and media order. Forty public SDK HTTP/SSE cases use those expectations plus independent custom-definition goldens; neither expected tool schemas nor content is generated by production conversion. Separate cases cover parallel same-name reverse-order association, a single valid Chat tool turn, errors, opaque nested citations, custom-array bounds/Unicode and source immutability. These are request-history fixtures with ordinary text replies, not tool execution, result-delta streaming or real image/PDF parsing.

`files/inline-pdf.json` independently authors four native full requests and four full target goldens. Twelve directions and roundtrips verify ordered text/files, raw bytes containing NUL/non-UTF-8 data and full function-call/result history. The media bytes are opaque transport samples, not renderable PDF documents. Forty-two separate public SDK HTTP/SSE cases cover final wire bodies, filename consent, provider references rejected before HTTP and URL reference transfer without an SDK download. A dedicated Chat text stream avoids substituting another protocol's events. Metadata/MIME/Base64/role/reference rejection cases complement the snapshots; no fixture is generated from production conversion output or live models.

`citations/url-citations.json` independently specifies complete native Chat/Responses replies and both complete target goldens, including Unicode text/titles, unchanged ranges, repeated-order assertions and URL query/fragment strings. It is authored from native structures, not converter output. Separate tests exercise multi-block ASCII offset rebasing, unknown Unicode-prefix rejection, tool identity, malformed fields and original-data retention. `UrlCitationFixtures.Stream` independently authors a nine-event Responses citation transcript to assert the native-copy and explicit cross-protocol strict/consented-loss boundaries; it does not claim converted citation streaming support or live search.

`source/` contains independently authored native request, complete-response and full stream transcripts for the four protocols. They include Unicode text, tool definitions, a stable original call ID, arguments/results, zero/false/null values, complete done events, usage and representative response envelopes. These are offline protocol examples, not captured live calls.

`golden/` contains separately specified target wire structures for the same semantic case. Expected JSON was authored from the protocol shapes, without invoking the production converter. Snapshots compare all object values and array/event ordering; object property order is insignificant. IDs, tool arguments and terminal events are not normalized away. Tests never rewrite fixtures automatically.

Known response envelope metadata and executed-request echoes remain available in `OriginalData` / `Metadata.Conversion.UpstreamData`. They are not interpreted as target requests or translated continuation state. Content, unknown fields and nested semantic configuration remain subject to conversion validation. Snapshot tests supplement the field, identity, HTTP pipeline and adversarial lifecycle tests; they do not replace them or prove model acceptance.

`schema/response-format.json` separately specifies complete modern Gemini, Chat, Responses and Claude requests for one structured-output case. Six directional snapshots check the complete target body, including unchanged Schema constraints, MIME enum versus legacy names, explicit output limits and wrapper metadata diagnostics. They are authored fixtures rather than converter-generated expected output; separate public SDK HTTP/SSE and negative cases verify actual transport wiring and strict rejection.

`schema/typed-source.json` independently specifies one complete typed Gemini source and complete Chat, Responses and Claude targets. Its nested types, nullable enum, quoted integer limits, zero/false/null, arrays, anyOf and example/default annotations are hand-authored. Three complete-request snapshots and six HTTP/SSE cases compare these expectations; separate adversarial tests cover exact int64 exponent/range handling, ProtoJSON names/nulls, property insertion order, alias conflicts and hard failure before HTTP for unsupported constraints. These fixtures verify the typed source output-schema dialect only, not typed target output.

`schema/typed-function.json` independently specifies the Gemini typed function definition and complete Chat, Responses and Claude request histories. Three snapshots and six final-wire HTTP/SSE cases retain the schema, named tool choice, call ID, argument JSON and result association. Each pure-data direction also replays the history back to Gemini while retaining the converted JSON Schema. Conflict/order/unknown-constraint/native-copy and pre-HTTP rejection cases complete the eighteen-test function-source checkpoint. No expected body is generated by the converter.

`schema/typed-target.json` independently specifies complete Chat/Responses/Claude sources and typed Gemini targets, separating strict OpenAI property-order guarantees from unordered Claude schemas. Three complete-request snapshots include reverse Schema replay, while six public HTTP/SSE cases verify final wire payloads and native operation paths. Separate tests reject unsupported constraints, enum/union changes, numeric rounding and pre-HTTP failures; they also cover annotation-loss consent, explicit selection, native-copy behavior and Session invalidation.

The independent `schema/typed-function.json` sample also covers typed function targets in reverse: three complete target snapshots with full roundtrip history and six final-wire HTTP/SSE cases. The separate 24-case target checkpoint validates all text/function dialect combinations, default/native copying, unsupported constraints, pre-HTTP failure and option binding. It does not generate expected definitions or histories from the conversion implementation.

`files/utf8-text.json` independently specifies complete Responses/Claude/Gemini pure-text file requests with two documents, surrounding text and original function/result history. Expected Base64 values correspond to authored UTF-8 text including emoji, combining marks, CRLF, NUL and BOM; no production converter generated them. Six directional full-target/replay comparisons and public HTTP/SSE cases verify document containers and links. Chat non-PDF file blocks have no positive fixture because the official contract supports PDF only.

`grounding/stream-to-responses.json` independently specifies a cumulative single-text-part Gemini source, the full native request, a fifteen-event Responses target and complete UTF-16/UTF-8 annotation tables. Emoji, combining marks, repeated text/URLs, empty ranges, pending sources and metadata/usage tails distinguish association from substring guessing. Unit offsets are hand-calculated; expected events are not produced by the converter. The fixture is an explicit endpoint-convention example, not real Google Search output.

`grounding/openai-to-gemini.json` specifies six complete Chat/Responses sources with declared index units, two independently authored Gemini targets and final HTTP request snapshots. Emoji, combining marks, repeated text, repeated URL/title pairs and a function between Responses text parts distinguish text-block offsets from original part indices. Expected byte ranges are hand-maintained; neither target snapshots nor range expectations are generated by the production converter. Tests also perform semantic roundtrips without equating vendor-local item IDs or serialized argument whitespace.

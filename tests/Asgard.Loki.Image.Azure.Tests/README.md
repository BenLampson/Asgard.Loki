# Asgard.Loki.Image.Azure.Tests

Independent offline vectors cover the dated Azure deployment-scoped image generation JSON and multipart editing wire described in the [Microsoft reference](https://learn.microsoft.com/en-us/azure/foundry/openai/reference-preview). The dated public schema is pinned to `Azure/azure-rest-api-specs` commit `59c8e482c0403f60118e2a8dc7c4a88e435db8b0`, blob `30513c7e8f941f944091d857bb27e201c7fcf32e`. The schema's binary image fields do not establish OpenAI-style JSON image references; the native editing guide describes multipart. These fixtures do not introduce a v1 API profile.

The two complete JSON requests distinguish public routes, path deployments and optional body model. Two complete multipart byte goldens cover one original image and multiple images plus a separate mask, ordered repeated unknown fields, zero/false/null JSON text, literal empty text and CRLF prompts. Only the random boundary is a comparison placeholder. Native complete results retain all image bytes/URL spelling, exact large usage counts, revised prompts, Azure prompt/content filtering and unknown fields. The complete native error keeps its inner policy object. All identities, versions, media and upload bytes are fictional. Fixture preparation predates production; structural validation alone does not prove SDK behavior, Azure acceptance, pixels, content filtering outcomes or live availability. Native streaming is a separate implementation/verification checkpoint.

The complete JSON/multipart implementation is covered by 94 offline xUnit v3 cases, including two full byte goldens, URI/authentication binding, complete original results/errors, native field snapshots, upload role/ownership, replay rejection, request/response/upload bounds and cancellation/read/disposal failures. A separate 127 native stream cases bring this supplier suite to 221 offline cases.

Independent stream vectors add four complete generation/editing SSE wires, two complete streaming multipart goldens, original error events, one/two-output cases, interleaved unknown events and independent SSE event/name/id/retry. Each JSON payload has a separately stored original wire string. They follow the documented native `image_generation` / `image_edit` event shapes and preserve fictional original image strings, exact numbers, nulls/false/zero and Unicode. The multiple-output and optional DONE cases test explicit SDK completion policy; they are not captured Azure traffic or proof of native multi-image acceptance. A stream must provide its native final images and finish transport/ownership normally before the SDK reports whole-call success. Neither a requested partial count nor DONE alone supplies missing final images. No model/version defaults, pixels, URL fetching or live calls are involved.

Streaming checks compare complete original event strings and metadata, one/two/ten native output counts, original ordering, whole-edit completion, optional DONE control, missing/duplicate/cross-operation events, late errors, exact integer spelling, fractional timestamps, byte/length/UTF-8/resource/cancellation failures, snapshot timing, single-use enumeration and early stop. They do not certify real Azure multi-output acceptance or pixel quality.

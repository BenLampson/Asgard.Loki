# Asgard.Loki.Image.Azure.Tests

Independent offline vectors cover the dated Azure deployment-scoped image generation JSON and multipart editing wire described in the [Microsoft reference](https://learn.microsoft.com/en-us/azure/foundry/openai/reference-preview). The dated public schema is pinned to `Azure/azure-rest-api-specs` commit `59c8e482c0403f60118e2a8dc7c4a88e435db8b0`, blob `30513c7e8f941f944091d857bb27e201c7fcf32e`. The schema's binary image fields do not establish OpenAI-style JSON image references; the native editing guide describes multipart. These fixtures do not introduce a v1 API profile.

The two complete JSON requests distinguish public routes, path deployments and optional body model. Two complete multipart byte goldens cover one original image and multiple images plus a separate mask, ordered repeated unknown fields, zero/false/null JSON text, literal empty text and CRLF prompts. Only the random boundary is a comparison placeholder. Native complete results retain all image bytes/URL spelling, exact large usage counts, revised prompts, Azure prompt/content filtering and unknown fields. The complete native error keeps its inner policy object. All identities, versions, media and upload bytes are fictional. Fixture preparation predates production; structural validation alone does not prove SDK behavior, Azure acceptance, pixels, content filtering outcomes or live availability. Native streaming is a separate implementation/verification checkpoint.

The complete JSON/multipart implementation is covered by 94 offline xUnit v3 cases, including two full byte goldens, URI/authentication binding, complete original results/errors, native field snapshots, upload role/ownership, replay rejection, request/response/upload bounds and cancellation/read/disposal failures. Stream support remains a separate unimplemented native capability, not inferred from these passing nonstream tests.

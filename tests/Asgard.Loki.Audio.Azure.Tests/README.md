# Asgard.Loki.Audio.Azure.Tests

Independent deployment-scoped Azure audio fixtures use the official [TTS REST quickstart](https://learn.microsoft.com/en-us/azure/ai-foundry/openai/text-to-speech-quickstart?view=foundry-classic), [preview audio reference](https://learn.microsoft.com/en-us/azure/foundry/openai/reference-preview) and [GA transcription/translation reference](https://learn.microsoft.com/en-us/azure/foundry/openai/reference). TTS JSON is distinct from multipart file operations; API version and deployment are explicit target settings, not a public model route. Optional native body model stays distinct from deployment name.

`Fixtures/azure-audio.json` independently describes three full speech JSONs (with/without body model and omitted optional settings), complete transcription/translation multipart part headers/body values, original audio/WAV bytes, verbose JSON segments, CRLF SRT and full native nested errors. Python wave/Base64 and exact-number checks are independent of production code. Parameters/IDs/credentials/audio are fictional.

Public SDK tests compare complete native JSON and MIME part headers/bodies, independent route/deployment/body-model identity, optional model omission/injection, parameter snapshots and input position. Additional cases cover raw/non-UTF-8 errors, malformed state/format/Unicode, alias conflicts before I/O, explicit API version encoding, size/length policies, upload/response failures, borrowed factories/inputs and terminal withholding through final disposal/cancellation. All HTTP transports are replacements. These are offline protocol checks, not live account/model/deployment acceptance or recognition/translation/audio-quality proof.

# Asgard.Loki.LLM

## Native Realtime

`loki.LLM.Realtime.OpenAsync(model, callOptions, cancellationToken)` requires a target declaring `LlmProtocol.Realtime` and a provider implementing `IRealtimeAdapter`. The returned `IRealtimeConnection` exposes caller-driven `SendAsync(JsonObject)`, `ReadEventsAsync()` yielding original `RealtimeEvent` snapshots, explicit `CloseAsync` and async disposal. Complete-target Session affinity and validation apply; reconnecting does not recover remote history. Native errors, tool associations, audio and all response statuses remain in original `Data`. Normal transport closure does not establish generation success. Realtime does not share HTTP Responses continuation ownership or Audio business state. The [OpenAI package](../Asgard.Loki.LLM.OpenAI/README.md#native-realtime-websocket) documents initialization, limits and offline-only validation. There is no implicit conversion, tool executor, retry or background loop.

Responses WebSocket has optional contracts and SDK connection/Session enforcement. `loki.LLM.Responses.OpenWebSocketAsync(model, options)` requires `LlmTargetFeatures.ResponsesWebSocket`, the Responses protocol, and an `IResponsesWebSocketAdapter`. The [OpenAI provider](../Asgard.Loki.LLM.OpenAI/README.md#native-responses-websocket) supplies a native transport; custom adapters remain supported. Other providers and converting decorators do not implicitly gain this feature, and HTTP calls do not switch transports automatically. Legacy custom `IResponsesClient` implementations retain the default unsupported method.

The returned `IResponsesWebSocketConnection` belongs to the caller. Use `await using`, explicitly send native JSON events, and enumerate all server events with a single reader. Concurrent writes are serialized, while native `stream_id` lanes are preserved. On `response.create`, omit `model` or use the public alias passed to `OpenWebSocketAsync`; the SDK writes the fixed upstream model. `stream` and `background` are rejected rather than removed. Input is copied before waiting, and unknown/native opaque fields are preserved. Future control events remain native; the SDK does not execute tools.

Every send validates the original cached binding without creating a replacement. Known lifecycle events register response IDs to the same Session; creation/steering `previous_response_id` and explicit `response.cancel.response_id` require that ownership, including across HTTP and WebSocket calls. `response.steer` requires a nonempty response ID and preserves its native input; the SDK adds no steering or tool loop. Connection disposal does not delete the logical Session or dispose borrowed factories/stores. Session loss, changed bindings, cache errors, failed handshakes and cancellation propagate without retry/failover. State is checked again after awaited Session validation, so operations still awaiting the cache do not enter native send/read after the caller closes or disposes the connection. Closing a socket does not allow the cache to restore its server-side state. Native framing and terminal validation remain the adapter's responsibility; the OpenAI provider implements these checks. See the current [WebSocket event schemas](https://developers.openai.com/api/reference/resources/responses/websocket-events).

Native optional operations are advertised independently of protocol families. `loki.LLM.Responses.CompactAsync` uses `ResponseCompactionRequest` / `ResponseCompaction`; it requires a target declaring `LlmTargetFeatures.ResponsesCompaction` and a provider implementing `IResponsesCompactionAdapter`. The complete returned window stays opaque and caller-controlled. Optional `PreviousResponseId` is checked against Session ownership; a compaction result ID is not registered as a generated-response ID. Unsupported existing targets fail without rerouting. The default interface method keeps older custom `IResponsesClient` implementations usable and reports compaction as unsupported. See the [root compaction example](../../README.md#native-responses-compaction).

Independent SDK contracts and complete-target routing for Chat Completions, Responses, Claude Messages, Gemini generateContent, Ollama Chat/generate, Bedrock Converse/Nova, Realtime, Moderations, native text Completions, Hunyuan and Spark.

## Native text Completions

`loki.LLM.TextCompletions.CompleteAsync` and `.StreamAsync` use `TextCompletionRequest`, `TextCompletion` and `TextCompletionEvent`. A configured target must explicitly declare `LlmProtocol.TextCompletions`, and its provider must implement `ITextCompletionsAdapter`; merely claiming the protocol cannot replace an implementation. This native prompt-based protocol is separate from Chat Completions and from Ollama generate. The [Azure provider](../Asgard.Loki.LLM.Azure/README.md#native-text-completions) implements native JSON/SSE transport. The conversion decorator does not advertise it.

`TextCompletionRequest.Model` is the public route name. `Parameters` contains the native `prompt` and all endpoint parameters, preserving absent/null values, text/text batches, token/token batches, suffix, echo, logprobs, stop, filters and future fields without templates or message synthesis. The provider owns endpoint-specific validation and may reject unsupported shapes/options. The selected method owns `stream`; case-insensitive `model`/`stream` extension overrides, Undefined values and malformed original Unicode fail before cache/target work. A complete snapshot precedes asynchronous Session resolution, then only the fixed actual model and transport mode are written.

The result and each event retain full native JSON, original choice order/indices, text, logprobs, filter/usage data, unknown fields and reported upstream model, with public/actual target metadata kept separately. `TextCompletionEvent` additionally retains SSE event name, ID and retry hint without reconnecting. Providers own native byte/EOF/terminal/resource validation; the core does not aggregate text, infer completion, execute tools or retry. Existing complete-target/credential/provider binding and explicit first-binding coordination apply. Text completion IDs do not enter Responses continuation ownership, and an existing Session cannot switch protocol. `TextCompletions = 1024` is additive; previous protocol values and ordinary target fingerprints remain unchanged.

## Explicit credential kinds

`new LlmCredential(id, apiKey)` keeps the existing nonempty API Key contract. `LlmCredential.Anonymous(id)` is a separate, explicit no-authentication identity. It requires a stable nonempty ID, stores no Key, and throws when `ApiKey` is read. This prevents old native adapters, including direct OpenAI HTTP/SSE/compaction/WebSocket calls, from sending an empty Bearer value. JSON and `ToString` remain secret-free; the default API Key metadata shape is unchanged.

A provider opts into `ILlmCredentialSupport.SupportsCredential(LlmCredentialKind)` for each supported native authentication kind. Existing providers without that optional interface accept API Keys only. Module registration validates every configured target, including unused alternatives, before Session/cache/HTTP work; no automatic downgrade, Key borrowing or endpoint inference occurs. A converting decorator delegates support to its fixed upstream and cannot extend it through loss consent.

```csharp
var localIdentity = LlmCredential.Anonymous("local-instance");
// Register with the native Ollama provider or an application-owned provider
// that explicitly declares and implements LlmCredentialKind.Anonymous.
```

API Key fingerprints retain their previous byte representation, allowing valid existing Sessions to resume. Anonymous bindings use a separate fingerprint domain while retaining server, actual model, credential ID, protocol, provider implementation and configuration version. Authentication-kind changes or any of those target changes reject an old Session; they do not cause target reselection. Configuration collections are snapshotted, and concurrent first binding still uses the explicit distributed coordination contract.

This is an LLM-owned credential foundation; cloud token refresh/signing and other capabilities have separate contracts. Providers remain responsible for HTTP/header behavior; the core does not rewrite caller-owned HTTP defaults or probe servers. The separate [Ollama provider](../Asgard.Loki.LLM.Ollama/README.md) implements native Chat JSON/NDJSON and rejects default Authorization for anonymous targets. The credential prerequisite has 40 offline regressions; native Ollama adds 159 independent Chat/generate wire/result/event and transport/session boundary cases. No real authentication/model call was performed.

## External authentication identity

`LlmCredential.External(id, principalIdentity)` declares a stable external principal/reference without storing an API Key or short-lived token. Both identifiers are required; `PrincipalIdentity` is available only for this kind, and `ApiKey` throws. Default JSON and `ToString` expose the credential ID/kind without serializing the principal or any secret. It is separate from `Anonymous`, which still means no authentication.

```csharp
var identity = LlmCredential.External("cloud-credential", "configured-tenant/principal");
// A provider must explicitly support LlmCredentialKind.External and borrow
// the application's provider-specific token/signing source.
```

Providers opt in through `ILlmCredentialSupport`; legacy providers remain API-Key-only, and the existing Ollama provider does not support this kind. Converting decorators delegate their fixed upstream's declaration. The core does not acquire/refresh tokens, read environment credentials or add cloud dependencies. Direct legacy Key-only operations fail before HTTP/WebSocket dispatch instead of sending an empty credential.

External fingerprints use a separate domain with structured target/principal/provider components, so newline-containing references cannot move separators and collide with implementation identities. Changing principal, authentication kind, server/model/credential identity or provider configuration rejects an old Session; stable principal identity allows a provider-owned source to refresh short-lived tokens without putting them in this fingerprint. API Key and anonymous fingerprint bytes are unchanged and verified using independently constructed legacy cache entries. Concurrent first binding and snapshots retain the existing explicit coordination contract.

This prerequisite has tests (28 core, four conversion and six direct OpenAI boundaries). Azure native Chat/Responses SSE preserves delayed annotations and terminal boundaries; compact/WebSocket remain pending. No cloud login, actual token refresh or live model call is claimed.

The independent [Vertex provider](../Asgard.Loki.LLM.GoogleVertex/README.md) additionally uses External identities for native Gemini/Claude JSON/SSE. Its target model is the full project/location/publisher-model or tuned-endpoint resource, so existing complete-target Sessions bind that identity without new core protocols. Authentication refresh remains source-owned; Native candidate/block terminals and usage tails wait for EOF/disposal; other Vertex dialects remain pending. Tests verify native wire/events, ProtoJSON numeric forms, Claude body version/tools/signatures, identity and lifecycle, not cloud login or live acceptance. Claude uses the existing explicit ClaudeMessages protocol and a full Anthropic publisher resource; its native SSE additionally preserves raw block/tool association, signatures and cumulative usage, with delayed terminal/error handling through EOF and disposal. Default omitted Claude options preserve preceding Gemini provider binding bytes; explicit version or block-policy changes are fingerprinted. Omitted Claude block policy retains existing Gemini/Claude JSON bindings.

The same Vertex supplier package additionally exposes `GoogleVertexExpressLlmProvider`, a separate API-Key-only Gemini JSON/SSE adapter for explicit `publishers/google/models/{model}` short resources. It needs no token source and adds no core protocol. Standard provider authentication/binding stays unchanged; tests verify native data, identity, resource limits and explicit conversion integration without live credentials.

## Native Ollama operations

`loki.LLM.OllamaChat.CompleteAsync` / `StreamAsync` use `OllamaChatRequest`, `OllamaChatResponse` and `OllamaChatEvent` through optional `IOllamaChatAdapter`. Targets explicitly declare `LlmProtocol.OllamaChat`; existing default target flags remain unchanged. Messages and native extension JSON are snapshotted before awaited Session resolution. Only actual model and method stream mode change. Native tool IDs/history, images, thinking, `format` schema, `options`, unknown values and counters remain intact; there is no conversion to an OpenAI envelope.

The provider retains native errors and validates NDJSON identity/terminal boundaries without aggregating tool calls or executing them. Stream done/error records wait for normal EOF, declared length and transport disposal. Partial records remain incremental; truncation, late data, invalid Unicode and resource failures propagate without fabricated completion or retry. `OllamaChatEvent.IsTerminal` includes errors; check `IsError` for failed generation. Native generate has its own client described below; Ollama conversion remains follow-up work. Provider initialization, resource limits, support matrix and offline/live status are documented in its README.

## Native JSON snapshot encoding

Public native clients validate original DOM strings/property names and extension `JsonElement` strings **before** serialization and awaited Session resolution. This covers Chat, Responses, Claude, Gemini and both Ollama clients, including complete/streamed calls, plus Responses compaction. Bound Responses WebSocket sends apply the same check before snapshot/cache/send. Unpaired UTF-16 surrogates and malformed JSON string escapes fail; they cannot become replacement characters that change tool IDs, error text or unknown native fields. Streaming validation begins when enumeration starts.

Registration and fingerprint creation likewise validate model/target/credential/provider identities and Key text, while call resolution checks original model/Session/previous-response IDs. Valid target/key fingerprints and serialized metadata stay unchanged; no new protocol flag, package dependency or conversion algorithm version is introduced. Existing valid Sessions remain usable. Borrowed stores/coordinators/factories retain their ownership.

Valid Unicode is not normalized, filtered or rewritten: combining characters, emoji, BOM/NUL/CRLF, unknown fields, exact JSON numbers and optional null/false values retain their native form. This is an encoding boundary, not a model/schema capability validator. Caller-supplied custom `JsonValue`/converter serialization retains its caller-owned policy; the SDK does not reflect over business objects or execute their getters as a separate validation pass. A custom adapter or direct provider call still owns any serialization it performs outside the public-client snapshot.

Raw DOM regression tests verify Unicode validation before binding or HTTP. They directly construct raw DOM requests rather than allowing a test deserializer to repair them first. No live model call is made.

## HTTP Responses event ownership

Streaming HTTP registers a native response ID only on known `response.created`, `response.in_progress`, `response.queued`, `response.completed`, `response.failed` or `response.incomplete` lifecycle events. The native JSON `type` takes precedence, with SSE event name fallback. Unknown extension events remain complete native events; a nested business `response.id` does not grant `previous_response_id` ownership or trigger an empty-ID cache write. Tests verify positive registration before delivery, unknown-event preservation and rejection before HTTP when attempting to continue an unknown business ID. Complete-result registration and existing WebSocket rules are unchanged. Previously cached records are not automatically purged; the caller retains cache/Session lifecycle control.

### Optional protocol support declaration

`ILlmProtocolSupport.SupportsProtocol(LlmProtocol)` lets a caller-owned or composed adapter explicitly restrict its implemented protocol interfaces. Registration checks each single known protocol in every configured target, including unselected/backup targets. A false declaration fails before invocation; a true declaration still requires the matching adapter interface and independently validated optional operation features. None/unknown flags remain invalid under the existing configuration rules.

```csharp
// Optional on an adapter that actually implements the corresponding interfaces.
public bool SupportsProtocol(LlmProtocol protocol) =>
    protocol is LlmProtocol.ChatCompletions or LlmProtocol.Responses;
```

The callback is a deterministic in-memory configuration declaration. It must not inspect models over the network, obtain credentials, mutate routing or select another provider. Keep the provider/configuration immutable after registration and include behavior-affecting configuration in its existing BindingIdentity. This is protocol scope, not a promise that every field, operation or transport is implemented. Those remain documented/validated separately. Adapters that do not implement this optional contract retain exactly the previous interface-based behavior.

No new protocol flags, target fields, fingerprint algorithm or package dependencies are introduced. The contract lives in LLM, not Abstractions or the entry package. Regression cases verify the following behavior: valid legacy/declared complete and stream calls still run, disallowed targets fail eagerly, declarations cannot replace implementations, and invalid flags never reach the callback.

### Native Responses ownership versus converted output IDs

Responses complete/stream clients register continuation ownership only for results/events without conversion metadata. Converted IDs remain visible and unchanged in JSON, but do not create native `previous_response_id` records. This includes synthetic Converse labels and other protocol-native IDs projected into Responses. Passing such an ID back as a continuation fails before another adapter/HTTP call. Native Responses keep their existing whole-target/session ownership and continuation behavior; no ID prefix is used to distinguish the cases. This changes neither cache coordination nor target selection. Earlier cached converted IDs are not proactively scanned or purged; the conversion guard still rejects cross-protocol continuation when an older ownership record exists.

`Model` is SDK routing metadata and is excluded from the native body. The selected target carries the actual model for the supplier's URL; only method stream mode is written to the body. Full prompt or messages, native tools/arguments/history, response_format, original scalar/optional values and unknown JSON are preserved. No model field, template, generation defaults, history rewriting or tool execution is added. Root model/stream overrides, Undefined and malformed original Unicode fail before Session/cache access; the full native snapshot precedes its first async wait. Existing complete server/account/model/credential/adapter/protocol affinity and explicit first-binding coordination apply.

Completion Data retains the whole native result/success/errors/messages envelope. `WorkersAiTextEvent` is a separate native SSE record: `Data` is original SSE data text, `Json` is an immutable object for JSON data and null only for the actual `[DONE]` control text. It retains independent EventName/EventId/RetryMilliseconds and route Metadata. It never manufactures a JSON object, ID, usage, role or normalized completion for DONE. A business type/done field, event name or response text containing that marker does not select the terminal. Strict original Unicode, unique JSON members and object data are validated without normalizing valid payloads.

The adapter owns HTTP, native envelope/error semantics, genuine DONE, EOF, byte/length policies, resource closure and final cancellation before terminal publication. Core in-memory tests do not establish Cloudflare transport, model availability or output quality. Native identities do not enter Responses continuation ownership. Cache/coordinator/adapter remain borrowed; no automatic retry, failover, background read or model-format guessing is introduced. The [Cloudflare supplier](../Asgard.Loki.LLM.Cloudflare/README.md) implements the native text HTTP/SSE contract; the separate OpenAI supplier profile handles compatible Chat and supported non-streaming Responses explicitly.
